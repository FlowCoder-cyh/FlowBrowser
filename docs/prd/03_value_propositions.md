# 03. 가치 제안 (Value Propositions)

> [← PRD 목차](./README.md)

본 섹션은 **자체 브라우저로서 정당화되는 영역** 을 명시. 본 PRD 작성 시점 (2026-05-16) 기준 외부 제품·확장 상태를 인용. Chrome 확장으로 cover 되는 기능은 차별 가치 약함 — 확장이 구조적으로 어렵거나 권한·UX 비용이 큰 영역에 집중.

## 3.1 자체 브라우저의 4가지 정당화 축

| 축 | 핵심 | Chrome 확장과의 차이 |
|---|---|---|
| **A1. 대용량 로컬 인덱스** | SQLite + sqlite-vec 통합 + 마이그레이션·백업 운영을 제품 내부에서 일관 통제 | 확장도 `unlimitedStorage` 권한 + IndexedDB 으로 일부 가능. 단 sqlite-vec / 마이그레이션 / 대용량 벡터 인덱스 운영을 안정적으로 제공하기 어려움 |
| **A2. 다중 워크스페이스 격리** | 브라우저 레벨 cookies / cache / storage partition (Phase 2+) + 영구 워크스페이스 모델 | 확장도 논리적 workspace 구현 가능. 단 cookies/storage partition 까지 격리는 어려움 |
| **A3. 백그라운드 영구 작업** | main process worker — 사용자 세션 동안 인덱싱 / 임베딩 / 백그라운드 번역 안정 진행 | service worker 라이프사이클 (필요 시 로드, dormant 시 unload) 로 장기 작업 안정성 제한 |
| **A4. 시스템 통합** | OS 파일 / 클립보드 / 글로벌 단축키 (Cmd+K) / 시스템 트레이 / 다른 데스크톱 앱과 직접 통합 | Native messaging 등 우회 경로 존재. 단 권한·설치·배포·UX 비용 큼 |

이 4축은 Chrome 확장으로도 부분 가능하지만, 본 시스템이 **더 안정적이고 일관되게 제공**. 차별의 본질은 "기능 가능 여부" 가 아니라 "제품 품질·통제권·UX 비용".

## 3.2 Chrome 확장 대비 매트릭스 (9 항목, v04-direction §9 SSOT 갱신과 정합)

✅ = 안정·일관 제공 / ⚠️ = 가능하나 권한·UX·운영 비용 / ❌ = 구조적 제약.

| 영역 | Chrome 확장 (Sider / MaxAI / Glasp / Monica) | FlowBrowser AI |
|---|---|---|
| 사이드패널 + 페이지 Q&A | ✅ | ✅ (동등, A4 + A1 결합으로 강화) |
| 텍스트 선택 → AI 분석 | ✅ | ✅ (노트 + 자동 태그 추가) |
| **다중 워크스페이스 격리** | ⚠️ 논리 분리만 가능 / cookies·storage 격리 제한 | ✅ 자체 cookies/cache/storage 분리 (P2+, A2) |
| **수만 페이지 임베딩 인덱스** | ⚠️ unlimitedStorage 권한 + IndexedDB 가능하나 sqlite-vec / 마이그레이션 운영 부담 큼 | ✅ SQLite + sqlite-vec (A1) |
| **백그라운드 영구 인덱싱** | ⚠️ service worker 라이프사이클 (필요 시 로드, dormant 시 unload) | ✅ main process worker (A3) |
| **워크스페이스 단위 AI 메모리** | ⚠️ 단일 컨텍스트 (워크스페이스 자체 부재) | ✅ 격리 + 영구 (A2) |
| **OS 파일 / 클립보드 / 단축키 / 트레이** | ⚠️ Native messaging 우회 가능하나 권한·설치·UX 비용 큼 | ✅ 직접 통합 (A4) |
| **UI 완전 재설계** | ❌ 사이드/팝업 한정 | ✅ |
| **시간축 정밀 검색 (방문 시간 + 의미)** | ⚠️ 히스토리 API 한계 (제목·URL 단어 매칭) | ✅ 자연어 시간 + 의미 임베딩 결합 |

## 3.3 ChatGPT 웹 / Perplexity 대비 (2026-05-16 기준)

ChatGPT Projects / Perplexity Spaces 등이 프로젝트별 컨텍스트·파일 업로드를 이미 제공. 본 시스템의 차별 본질은 "프로젝트 격리 유무" 가 아니라 **"사용자가 실제 방문한 DOM 페이지를 workspace별로 자동 인덱싱하고 visit/dwell/cache와 연결"** — Projects/Spaces는 파일·지침 기반.

| 영역 | ChatGPT Projects / Perplexity Spaces | FlowBrowser AI |
|---|---|---|
| AI 채팅 | ✅ | ✅ (워크스페이스 메모리 retrieval 추가) |
| 프로젝트별 컨텍스트 | ✅ (파일 업로드 / 지침 기반) | ✅ (방문 페이지 자동 인덱싱 기반) |
| **사용자 방문 페이지 자동 인덱싱** | ❌ 수동 업로드만 | ✅ DOM 자동 추출 |
| **visit / dwell / 본문 캐시 연결** | ❌ | ✅ (재방문 시 변경 감지 + 시간 시그널) |
| **시간축 검색** | ❌ | ✅ |
| 출처 인용 (페이지 단위) | ⚠️ 업로드한 파일 인용만 | ✅ 사용자가 본 페이지에 인용 |

## 3.4 Recall.ai / Rewind.ai 대비 (2026-05-16 기준, 메모리 도구)

| 영역 | Recall / Rewind | FlowBrowser AI |
|---|---|---|
| 메모리 base | 화면 캡처 + OCR | 구조화된 DOM 추출 |
| 검색 정확도 | OCR 오류 누적 | 임베딩 (1k 차원) + content_hash dedupe |
| 시스템 부담 | 화면 캡처 상시 | DOM 추출 (페이지 열 때만) |
| 브라우저 통합 | 별도 앱 | 브라우저 내장 — 본 페이지에서 직접 AI 호출 |
| 워크스페이스 | ❌ | ✅ |

## 3.5 Arc / Arc Search 대비 (2026-05-16 기준, AI 브라우저 시장)

Arc은 Spaces / Profiles 기능으로 환경 분리 일부 제공. 본 시스템의 차별은 **사용자 방문 페이지 자동 인덱싱 + 시간축 의미 검색**.

| 영역 | Arc / Arc Search | FlowBrowser AI |
|---|---|---|
| AI 검색 | ✅ 검색 강화 (Arc Search) | ✅ + 워크스페이스 메모리 retrieval |
| 다중 환경 | ✅ Spaces / Profiles (탭 그룹·프로필 단위) | ✅ 워크스페이스 + 메모리·노트·AI 컨텍스트 격리 |
| **방문 페이지 자동 인덱싱** | ⚠️ 히스토리 기반 (제목·URL 중심) | ✅ DOM + 임베딩 |
| **시간축 + 의미 검색** | ❌ | ✅ |

## 3.6 사용자 가치 명제 (한 문장 요약)

> 사용자가 본 모든 페이지를 자동 기억하고, 프로젝트별 환경에서 격리하며, 시간축 + 의미 검색과 AI 채팅으로 횡단 분석할 수 있는 — Chrome 확장이 구조적으로 못 하는 영역에 집중한 자체 브라우저.

## 3.7 정당화의 한계 (정직한 명시)

본 시스템이 **모든** 영역에서 우월하지 않다. 정직한 한계:

- **단순 페이지 Q&A** 만이면 Chrome 확장으로 충분 — 본 시스템 도입 부담 (브라우저 변경) > 효용
- **브라우저 변경 비용** — Chrome 사용자 ↔ FlowBrowser 전환 시 즐겨찾기 / 확장 / 단축키 학습
- **데이터 잠금** — 본 시스템의 워크스페이스 메모리 → 다른 도구로 export 가능해야 함 ([§19 마이그레이션](./19_migration_v03_v04.md) Phase 3 Export)
- **확장 생태계 포기** — Chrome 확장 (광고 차단·번역·비밀번호 관리자 등) 사용 불가 → 본 시스템 자체 기능 또는 OS 도구 의존
- **개인정보·프라이버시 비용** — "모든 페이지 자동 인덱싱" 은 핵심 가치이자 가장 큰 리스크. 디폴트 차단 list + 비밀번호 필드 감지 ([§13](./13_security_privacy.md)) 로 완화하지만 사용자 신뢰가 본 시스템 도입의 전제
- **DOM 추출 실패 영역** — canvas / PDF / 로그인 페이지 / 동적 렌더링 페이지는 자동 인덱싱 정확도 떨어짐 ([§08 인덱싱](./08_indexing.md) 정책)
- **자체 브라우저 정당화의 중간 지대** — A1~A4 모두 "확장으로 불가" 가 아니라 "확장으로 어렵거나 권한·UX 비용 큼" — 명확한 단정이 아닌 정도의 차이
