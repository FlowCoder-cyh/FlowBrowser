# 01. Overview — 한 줄 정의 + 정체성 + 결격사유 0

> [← PRD 목차](./README.md)

## 1.1 한 줄 정의

> **본 페이지를 자동 기억하면서, 프로젝트별로 환경이 격리되는 AI 리서치 브라우저**

이름: **FlowBrowser AI** (변경 없음, v0.1 ~ v0.3 일관 유지)

핵심 가치 명제 4종:
1. **본 페이지 자동 인덱싱** — 사용자가 본 모든 페이지를 로컬 SQLite + 임베딩에 누적
2. **워크스페이스 격리** — 프로젝트별 탭 / 메모리 / AI 컨텍스트 / 노트 분리
3. **시간축 + 의미 검색** — "3개월 전 본 그 글" / "AI 관련 본 글 모아줘" 자연어 질의
4. **AI 횡단 분석** — 워크스페이스 메모리 retrieval로 비교·**종합·요약 (retrieval 기반)** ·Q&A

> 참고: 위 §4의 "종합·요약"은 v0.3 `SummarizationPlanner` (단일 페이지 요약, 폐기) 와 다른 개념. 워크스페이스 메모리에 누적된 다수 페이지를 retrieval 기반으로 묶어 종합하는 신규 기능.

## 1.2 적용 패러다임

### 1.2.1 폐기된 패러다임 (v0.3)

| 패러다임 | 폐기 사유 |
|---|---|
| **실시간 페이지 번역** (replace / overlay) | Chrome 내장 번역 대비 차별 약함 + 호출 폭증 (페이지당 49+회) → ChatGPT 한도 5h/주 즉시 소진 |
| **YouTube 자막 / TTS 더빙** | Chrome 자동 자막 + 시스템 TTS로 충분, 차별 약함 |
| **STT** | OS별 호환성 부담 vs 효용 낮음 |
| **페이지 요약 (SummarizationPlanner)** | 새 방향에서 워크스페이스 메모리 retrieval 기반으로 다른 형태 |

### 1.2.2 신규 패러다임 (v0.4)

| 패러다임 | 정의 | 차별 |
|---|---|---|
| **자동 인덱싱 (passive)** | 사용자가 본 페이지 자동 DOM 추출 + 임베딩 | Chrome 히스토리는 제목/URL만, 본 시스템은 본문 + 의미 인덱스 |
| **워크스페이스 (project-centric)** | 프로젝트별 환경 격리 (탭/메모리/AI/노트) | Chrome 단일 환경 vs 본 시스템 다중 워크스페이스 |
| **시간축 + 의미 검색 (Cmd+K)** | 자연어 시간 ("6개월 전쯤") + 의미 매칭 | Chrome 히스토리는 제목 단어 매칭만 |
| **AI 채팅 retrieval (RAG)** | 워크스페이스 메모리 top-k retrieval + 출처 인용 | ChatGPT 웹은 단일 페이지 컨텍스트만 |
| **백그라운드 번역 (P2)** | 논문/PDF 시간 걸려도 백그라운드 + 알림 | Chrome 번역 vs 본 시스템 깊이 있는 LLM 번역 (시간 무관) |

## 1.3 정체성 — 자체 브라우저 정직한 식별

### 1.3.1 User-Agent (Brave/Edge/Vivaldi 패턴)

```
Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
(KHTML, like Gecko) Chrome/130.0.0.0 Safari/537.36 FlowBrowserAI/0.1.0
```

- Chromium 호환 토큰 유지 → 사이트 표준 모드 응답 보장
- `FlowBrowserAI/0.1.0` 자체 식별 토큰 추가 → 정직한 정체성 명시
- **위장 X** — Electron 토큰 제거 같은 hack 금지

### 1.3.2 정체성 원칙 3개

1. **Chromium 호환** — Chrome 호환 토큰 유지로 사이트의 표준 응답 기대 (개별 사이트의 정책·구현에 따라 실제 동작은 사이트가 결정)
2. **자체 브랜드 식별** — `FlowBrowserAI` 토큰 추가, 사이트 입장에서 "Brave/Edge/Vivaldi처럼 또 하나의 브라우저"
3. **위장 금지** — fingerprint 변조 / 헤드리스 위장 / Chrome 척하기 모두 금지

이 정체성은 **사이트에서 추가적인 봇 의심 패턴을 만들지 않음** 을 보장 (사이트가 차단할지 여부는 사이트 정책 결정 사항).

## 1.4 결격사유 0 원칙

> **"결격사유 0"**: 사이트 입장에서 본 브라우저를 차단 / 봇 탐지 / 비정상 트래픽으로 분류할 사유를 시스템 차원에서 만들지 않는다는 원칙. 자체 브라우저는 **모든 사이트에서 정상 동작 + AI 레이어가 부가** 되어야 메리트. 다음을 절대 하지 않음:

### 1.4.1 금지선 (G-003 + G-011 + 본 §1.4 강화)

| 금지 항목 | 이유 |
|---|---|
| 헤드리스 모드 | 봇 탐지 트리거 (Cloudflare/reCAPTCHA) |
| fingerprint 변조 / 위장 | 정체성 원칙 위반 + 신뢰 붕괴 |
| **자동 prefetch / 크롤링** | 봇 의심 패턴 — 사용자가 안 본 페이지를 시스템이 자동으로 fetch 안 함 |
| AI가 페이지 자동 조작 (에이전트) | 사용자 트리거 없이 form 입력 / 버튼 클릭 X |
| ChatGPT 웹 세션 / 쿠키 재사용 | G-003 인증 금지선 |
| 사용량 한도 우회 | G-003 |

### 1.4.2 동작 원칙

- **페이지 호출 = 사용자가 직접 연 페이지만**. 자동 prefetch / 크롤링 / 백그라운드 fetch 안 함.
- **AI 호출 = 사용자 본인 credential (API Key 또는 OAuth)** 로 OpenAI / Codex에 별도 호출. 사이트와 무관 (사이트 입장에서 우리 AI 호출 트래픽 안 보임). 자동 백그라운드 호출 (인덱싱·임베딩·태깅) 은 **BYOK (API Key) 디폴트**, Codex OAuth는 사용자 명시 동의 시에만 (G-003 강화).
- **인덱싱 = 사용자가 본 페이지의 DOM만 사용** (페이지 재 fetch 안 함). 사용자가 안 본 페이지는 인덱싱 안 함.
- **사용자 능동 호출 (AI 채팅 요청)** 은 사용자가 선택한 Provider (API Key / Codex OAuth 모두 가능) 사용.

### 1.4.3 결과

사이트 입장에서는 **또 하나의 Chromium 호환 브라우저**일 뿐. 본 시스템 차원에서 추가적인 봇 의심 패턴을 만들지 않음 (사이트의 정책·구현에 따른 차단 가능성은 별개로 사이트의 결정 사항).

## 1.5 Chrome 확장 대비 자체 브라우저의 정당화

Chrome 확장 (Sider / MaxAI / Glasp / Monica)이 단순 AI 보조 도구는 이미 cover. 자체 브라우저가 정당화되려면 **확장이 못 하는 영역**에 집중해야 함.

| 영역 | Chrome 확장 | FlowBrowser |
|---|---|---|
| 사이드패널 + 페이지 Q&A | ✅ | ✅ (동등) |
| **다중 워크스페이스 격리** | ❌ 단일 환경만 | ✅ 자체 cookies/cache/storage 분리 (P2+) |
| **수만 페이지 임베딩 인덱스** | ❌ IndexedDB 용량 제약 | ✅ SQLite + sqlite-vec |
| **백그라운드 영구 인덱싱** | ❌ service worker 제약 | ✅ main process worker |
| **워크스페이스 단위 AI 메모리** | ❌ 단일 컨텍스트 | ✅ 격리 + 영구 |
| **OS 파일 / 클립보드 / 단축키 / 트레이** | ❌ sandbox | ✅ |
| **UI 완전 재설계** | ❌ 사이드/팝업 한정 | ✅ |
| **시간축 정밀 검색** | ⚠️ 히스토리 API 한계 | ✅ |

상세: [`03_value_propositions.md`](./03_value_propositions.md).

## 1.6 사용자 가치 명제 (한 문장 요약)

> 사용자가 본 모든 페이지를 자동 기억하고, 프로젝트별 환경에서 격리하며, 시간축 + 의미 검색과 AI 채팅으로 횡단 분석할 수 있는 — Chrome 확장이 못 하는 영역에 집중한 자체 브라우저.
