# 데일리 핸드오프

매 작업 종료 시 본 디렉토리에 `YYYY-MM-DD.md` 형식으로 작성한다.

## 목적

- 세션 간 컨텍스트 손실 방지
- 다음 세션 시작 시 즉시 작업 가능 상태 복원
- 결정 사항·발견 사항·막힘의 이력 보존
- Phase 종료 시 회고 입력

## 작성 양식

```markdown
# YYYY-MM-DD 핸드오프

## 메타
- Phase: 0 | 1 | ...
- 활성 Spike / Sprint:
- 세션 시간: HH:MM ~ HH:MM (대략)

## 오늘 한 일
- 항목 1
- 항목 2

## 결정 사항
- 결정 1 — 근거
- 결정 2 — 근거

## 발견 사항
- 가드레일 추가: G-NNN (있으면)
- 도메인 개념 추가: ontology.md 어느 항목 (있으면)
- PRD 갱신 필요: 어느 섹션 (있으면)

## 막힘 / 미해결
- 항목 + 다음에 해볼 것

## 다음 작업
- 우선순위 1
- 우선순위 2

## 다음 세션 컨텍스트
- 읽어야 할 파일
- 기억해야 할 결정
- 잊으면 안 되는 맥락

---FLOWSET_STATUS---
PHASE: ...
SPIKE_ACTIVE: ...
TASK: ...
NEXT: ...
HANDOFF_NEEDED: false
---END_FLOWSET_STATUS---
```

## 갱신 규칙

- 작성 후 `state.md`의 "최근 갱신" 일자 동기화
- `guardrails.md` / `ontology.md` 변경이 있으면 본 핸드오프에 명시
- 한 일이 적은 날도 작성 (최소 1줄이라도)
- 같은 날 여러 세션이면 같은 파일에 이어쓰기 (시간으로 구분)

## 누적 활용

- 주말 / 월말 회고 시 핸드오프 누적 → 추세 파악
- Phase 종료 회고 시 Phase 내 모든 핸드오프 검토
- evaluator가 Phase 회고 입력으로 사용

## 파일명 규칙

- 형식: `YYYY-MM-DD.md` (예: `2026-05-11.md`)
- 같은 날 여러 핸드오프 필요 시: `YYYY-MM-DD-N.md` (N=2,3,...) — 권장하지 않음, 한 파일에 통합 우선
