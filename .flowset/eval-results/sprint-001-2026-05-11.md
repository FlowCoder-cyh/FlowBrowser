- **결과**:
  - `src/storage/Credentials.ts`: `safeStorage.isEncryptionAvailable()` 가드 후 `encryptString` → base64 → `credentials.json`의 `encryptedSecret` 컬럼만 저장. `toPublic()`에서 암호값 제거 → IPC 응답에 secret 노출 없음.
  - `OpenAIApiKeyProvider`는 `secretProvider: () => credentialsStore.decryptSecret('openai')` 클로저 — 인스턴스 필드에 평문 secret 미보관.

- **결과 (실제 OS Keychain 등록)**: macOS Keychain Items.app / Windows `cmdkey /list` 실제 확인은 **수동 QA 필요**.
- **판정**: **Partial** (코드 측 완성, 실 등록 확인은 수동 QA)
- **근거**: G-005 정합 코드 완비. 단, `safeStorage`가 실 macOS/Windows에서 OS Keychain에 위임하는 동작 확인은 GUI 실행 + OS 도구 검사가 필요하므로 단정 불가.

## 회고 (Sprint Retrospective)

### 잘된 점
1. **단일 작업일 M1~M3 머지** — Phase 0 Spike 5종 + PRD v0.3 발행으로 요구사항 모호성이 사전 제거되어, 본 Sprint는 "코드만 작성"이 가능했다. FlowSet 계약 명세가 직접 작업 단위로 분해 가능한 형식이었음.
2. **G-004 게이트 단일 진입점화** — `executeTranslateRequest` 함수 추출로 IPC 경로(`translate:request`)와 main process 직접 호출(context-menu) 모두 동일 게이트 통과 강제. 우회 경로가 코드 수준에서 차단됨.
3. **39개 Privacy 단위 테스트** — Sprint 핵심 가드레일 G-004를 객관 검증 자료로 보유. 향후 리팩토링 시 회귀 방지 안전망 확보.
4. **`safeStorage` 클로저 패턴** — `decryptSecret: () => credentialsStore.decryptSecret('openai')`를 Provider에 주입하는 패턴으로, secret 평문이 인스턴스 필드에 남지 않게 설계. G-005 정합 깊이 강화.
5. **OS 표준 context-menu 활용** — T08 SelectionExtractor를 별도 content script 주입 없이 Electron `params.selectionText`로 해결, 외부 페이지 sandbox 유지하면서 selection 획득.

### 어려웠던 점
1. **계약 산출물 경로 vs 실제 경로 차이** — T08 `src/perception/SelectionExtractor.ts` 경로가 계약에 명시됐으나 OS context-menu로 대체 구현됨. evaluator가 "위치는 다르나 책임은 동일"로 합리성 판정. **학습**: 계약 산출물 경로는 책임을 표현하는 것이지 파일 위치가 강제는 아님.
2. **수동 QA / 객관 검증 경계** — 단일 작업일 머지로 인해 실 GUI 시연 자료가 evaluator에게 전달되지 않음. AC-1·3·4·5는 모두 Partial 판정 (Fail 아님). **학습**: 수동 QA 결과를 핸드오프나 PR 본문에 캡처/로그 형태로 첨부하면 evaluator가 단정 가능.
3. **AC-6 사용자 표시 UI 미구현** — 데이터 계층 완성 후 UI 표시는 "M3·M4 잔여"로 미뤄짐. SettingsPage에 "추후 추가" 표기로 가시화. **학습**: AC를 데이터/UI 두 축으로 분리해 계약에 명시하면 Partial vs Fail 경계가 명확해짐.
4. **ESLint CI 통합 지연** — 스크립트는 존재하나 CI 게이트는 다음 PR로 분리. AC-7이 Partial로 남음. **학습**: CI 게이트는 Sprint 초입 PR에 포함하는 편이 후속 Sprint의 회귀 방지에 유리.
