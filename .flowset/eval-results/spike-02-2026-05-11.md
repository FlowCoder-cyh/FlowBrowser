## 항목별 채점

### 1. YouTube IFrame Player API 기능 정합성

- 임계: 공식 docs(developers.google.com/youtube/iframe_api_reference)와 일치하는 메서드/이벤트 매트릭스 제시
- 결과:
  - `playVideo / pauseVideo / stopVideo / seekTo / getCurrentTime` 명시 — 공식 reference와 일치
  - `getPlaybackRate / setPlaybackRate(0.25~2)` 명시 — 공식 허용 단계와 일치
  - `getVolume / setVolume(0-100) / mute / unMute / isMuted` 명시 — 공식과 일치
  - 자막 항목: `getOptions('captions')` + `setOption('captions', 'track', {languageCode})` 명시 + **`onAPIChange` 이벤트 후에만** 사용 가능하다는 제약 명시 — 공식 동작과 일치
  - postMessage 메시지 형식 (`event=command, func, args, id, channel=widget`) 명시 — David Hu 분석 글과 일치
- 판정: **Pass**
- 근거: 공식 reference 9개 핵심 메서드를 빠짐없이 매트릭스화했고, 각 항목의 제약(예: captions는 onAPIChange 이후)까지 정확히 표기. 출처 4개(공식 2 + 3rd-party 분석 2) 제시.

### 2. 자막 추출 방식 분석 (공식 vs 비공식 구분 및 Spike 1 패턴 일관성)

- 임계: 공식 API와 비공식 경로를 명확히 분리하고, 회색지대를 회색지대로 명시 + Spike 1 회색지대 패턴과의 일관성 유지
- 결과:
  - 4가지 경로를 표로 분리:
    1. YouTube Data API v3 `captions.download` — 공식, 본인 영상만 (즉 3rd-party 영상에 무용)
    2. IFrame API `getOptions('captions')` — 공식, 트랙 변경만, 텍스트 추출 불가
    3. caption track URL 직접 호출 (`timedtext.googlevideo.com`) — **회색지대** 명시
    4. 비공식 transcript 라이브러리 (youtube-transcript-api 등) — **회색지대** 명시
  - 결론에 "Spike 1 (Codex OAuth) 회색지대 패턴과 동일" 명시 — 일관성 유지
  - Spike 1 비교: Spike 1은 "공개 Codex OAuth 클라이언트 재사용 → 회색지대 허용 (OpenAI 묵인)", Spike 2는 "caption track URL 직접 fetch → 회색지대 허용 (공식 차단 없음)" — 동일 패턴
- 판정: **Pass**
- 근거: 공식/비공식 경계가 표로 명확하게 분리되었고, 회색지대를 회색지대로 정확히 라벨링. Spike 1 패턴과 명시적 일관성 유지(spec 본문 결론부 + 판정 조건 1번).

### 3. 임베디드 YouTube 동작 분석 객관성

- 임계: 직접 접속 vs iframe 임베디드 vs Electron BrowserView 환경별 동작 비교 + 측정 가능한 근거 제시 (또는 Phase 1 이관 명시)
- 결과:
  - 4가지 환경(youtube.com 직접 / iframe 임베디드 / Electron BrowserView 직접 / Electron BrowserView 임베디드)을 매트릭스화
  - 모두 ✓ 처리 + 근거: "Chromium 동일, postMessage cross-origin 표준"
  - **단**, 임베디드 환경의 실제 동작은 spec에 "Phase 1 PoC 이관" 5번으로 명시 ("임베디드 YouTube (블로그/강의 플랫폼)에서 실제 동작 매트릭스")
  - **자막 텍스트 추출은 postMessage로 못 받음 → caption track URL 직접 fetch 필요** 명시 — IFrame API 제약 정확히 인지
- 판정: **Partial**
- 근거: 분석 자체는 객관적이고 출처 기반이지만, 실 환경 측정값(예: postMessage 응답 지연, 임베디드 iframe에서 광고 삽입 시 무력화 빈도)이 없음. spec 자체가 "정책·스펙 조사 1차" 단계임을 명시하고 Phase 1 이관 항목으로 옮긴 점은 객관적. P-001 원칙 "측정 데이터 부재 시 Pass 불가"에 따라 Partial.

### 4. DRM / 연령 제한 / 광고 환경 제약 데이터 출처 명확성

- 임계: 환경 제약 데이터에 명시적 출처 + 모호한 경우 모호함을 모호함으로 표기
- 결과:
  - DRM: "TV 클라이언트(TVHTML5) 한정 DRM 적용, 일반 IFrame 무관" — Hacker News 출처 + Muvi 출처 명시
  - 연령 제한: "사용자 본인 로그인 + 연령 확인 필요. Electron 세션이 인증되면 가능" — Google YouTube Help 출처 명시
  - Premium 전용: "미공개 영상 등, 임베드 자체 거부" — 출처 표기 없지만 일반 상식 수준
  - 광고: "광고 자체는 별도 영상, 재생 제어 일부 무력화 가능" — 출처 표기 없음, △ 표기로 모호함 인정 + Phase 1 측정 이관 3번으로 명시
  - 임베드 비활성: 제작자 설정 — 출처 표기 없지만 YouTube Studio 공개 기능
- 판정: **Partial**
- 근거: DRM / 연령 제한은 출처 명확. 광고 구간 동작은 출처가 없으나 "△ + Phase 1 측정 이관"으로 모호함을 모호함으로 정직하게 표기. P-001(객관성) 적용 시 광고/Premium 항목의 출처 미비로 Pass 불가, 그러나 spec이 △ 표기와 Phase 1 측정 이관으로 정직하게 처리한 점은 인정 → Partial.
