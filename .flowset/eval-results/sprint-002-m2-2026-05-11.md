## 항목별 채점

### T03-1 TranslationCache 클래스 — 복합 키
- 임계: (sourceHash + sourceLanguage + targetLanguage + providerType + glossaryVersion) 5개 요소 결합
- 결과: `TranslationCache.buildKey()`가 sha256(sourceText) + 4개 필드를 `|` join 으로 합성 (`TranslationCache.ts:65-75`). glossaryVersion 미지정 시 `'default'` 폴백
- 판정: **Pass**
- 근거: PRD §12.4 조회 키 정의와 1:1 정합. 테스트로 4개 요소 변화 시 composite 분리 검증

### T03-2 TTL 기본 90일 / 자막 365일
- 임계: 기본 90일 / 자막 365일 (PRD §12.4)
- 결과: `DEFAULT_TTL_MS = 90 * 24 * 60 * 60 * 1000`, `SUBTITLE_TTL_MS = 365 * 24 * 60 * 60 * 1000` (`TranslationCache.ts:44-45`). `store({isSubtitle: true})` 분기로 365일 적용
- 판정: **Pass**
- 근거: 테스트에서 두 TTL 모두 측정 검증 (`TranslationCache.test.ts:161-191`)

### T03-3 JSON 영속 + writeQueue 보호
- 임계: 디스크 영속 + 동시 쓰기 직렬화
- 결과: `persistOnce()`가 `writeQueue = writeQueue.then(persistOnce)` 체이닝으로 직렬화 (`TranslationCache.ts:222-225`). `flush()` 제공으로 테스트에서 보장 가능
- 판정: **Pass**
- 근거: persistence 테스트에서 cache1 → flush → cache2 재로드 시 hit 확인

### T03-4 LRU 만료 (1GB 초과)
- 임계: maxBytes 초과 시 LRU 정렬 후 절반 제거
- 결과: `persistOnce()` 내부에서 `Buffer.byteLength(serialized) > maxBytes` 시 lastAccessedAt 내림차순 정렬 → 상위 절반 보존, 디스크에도 trimmed 저장 (`TranslationCache.ts:231-242`)
- 판정: **Pass**
- 근거: 로직 자체는 명확. (테스트는 만료 expiry 기준만 검증하지만 단위 검증 13개 + PRD §12.4 "용량 한도 1GB, 초과 시 LRU 만료" 명세 일치)

### T03-5 invalidateByGlossaryVersion / clearAll
- 임계: 용어집 버전별 무효화 + 전체 삭제
- 결과: `invalidateByGlossaryVersion(version)`은 해당 entry만 제거 후 카운트 반환. `clearAll()`은 메모리 + 디스크 unlink (`TranslationCache.ts:155-178`)
- 판정: **Pass**
- 근거: glossary invalidation 테스트로 v1만 제거되고 v2 hit 유지 확인. clearAll 테스트로 ENOENT 확인
