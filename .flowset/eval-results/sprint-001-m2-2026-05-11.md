### A. T04 Privacy Layer 골격 (SensitiveFieldDetector / DomainFilter / ConsentGate / TransmissionLogger)

- 임계: G-004 / PRD §9.6. password / 카드 / 도메인 블랙리스트 3축 + 전역 동의 + 세션 토큰 + 전송 로그.
- 결과:
  - `SensitiveFieldDetector.ts` — `<input type="password">` 직접 selector, 카드 힌트 정규식 7종(`cc[-_]?num` / `card[-_]?number` / `cvv` / `cvc` / `exp` / `payment` / `credit-card`), Payment Request API(`'PaymentRequest' in window`) 폴백, 텍스트 본문 카드 패턴 `\b(?:\d[ -]*?){13,19}\b`. `executeJavaScript` 직렬화를 위한 `detectSensitiveFieldsScript()` 별도 제공.
  - `DomainFilter.ts` — 기본 13개 패턴(`mail.` / `accounts?.` / `banking.` / `payment.` / `pay.` / `checkout.` / `login.` / `signin.` / `oauth.` / `id.` / `.bank$` / `gmail.com$` / `paypal.com$`). 사용자 룰 (`whitelist > user_blacklist > default_blacklist`) 우선순위.
  - `ConsentGate.ts` — 전역 동의 + `policyVersion` 변경 시 재동의 강제, 세션 토큰 `randomUUID` + TTL 기본 1시간 + 만료 자동 purge + one-shot `consumeApprovalToken`.
  - `TransmissionLogger.ts` — JSONL 영속화(`appendFile` 큐), blocked는 메모리 카운터(byDomain / byReason / total)에만 기록 (PRD §12.8 정합 — UsageLog의 `privacyDecision`은 `allowed | user_approved`만 허용).
  - `index.ts::evaluatePrivacy` — consent → password → card field → text card pattern → domain 5단계 게이트, 수동 승인 토큰 모든 사유 우회 가능, 통과 시 토큰 자동 consume.
- 판정: **Pass**
- 근거: 계약 산출물 4개 파일 모두 존재 + G-004 게이트 5단계 모두 구현 + 평가 우선순위 명확. 기본 블랙리스트는 계약의 8개 패턴을 초과(13개)하며 사용자 룰 + 통계 카운터 모두 구현.

### D. T07 OS Keychain (Credentials.ts) — G-005 정합

- 임계: secret을 앱이 보관하지 않음. `safeStorage.encryptString` 사용. 평문은 호출 즉시 폐기 책임 명시.
- 결과:
  - `safeStorage.isEncryptionAvailable()` 가드 후 `encryptString` → base64 → `credentials.json`에 `encryptedSecret` 컬럼만 저장.
  - `PersistedRecord`에서 `encryptedSecret` 컬럼은 `toPublic()`에서 제거 → `list()` / IPC 반환값에 평문/암호 secret 노출 없음.
  - `decryptSecret(providerType)`는 호출 시점에만 평문 반환. `OpenAIApiKeyProvider`는 `secretProvider: () => credentialsStore.decryptSecret('openai')` 클로저로 호출 즉시 사용 — 인스턴스 필드로 보관하지 않음.
  - 주석에 "메모리에 오래 보관 금지" 명시.
- 판정: **Pass**
- 근거: G-005 (앱이 secret 보관 안 함) 정합. `credentials.json`에는 암호화된 base64만 + Electron `safeStorage`가 macOS Keychain / Windows DPAPI / Linux libsecret으로 위임. 다만 `decryptSecret` 반환값이 일반 `string`이라 GC 시점까지 V8 메모리에 잔존하는 한계는 Electron 환경 일반 한계 (별도 mitigation 항목으로 분류, Fail 사유 아님).

- 임계: 모든 서비스 init + IPC 핸들러 5세트(consent / credential / privacy / usage / translate).
- 결과:
  - `initServices()` — userData 디렉토리 기준 4개 파일(consent.json / domain-filter.json / transmission-log.jsonl / credentials.json / usage-log.jsonl) 초기화.
  - `consent:get/give/revoke` (3개), `credential:list/save/delete/validate` (4개), `privacy:scan-page/approve/add-rule/remove-rule/get-rules/blocked-stats` (6개), `usage:summary/list` (2개), `translate:request` (1개) — 총 16개 IPC.
  - `translate:request` 흐름: `extractDomain(url)` → `evaluatePrivacy` → blocked면 `transmissionLogger.recordBlock` + return → Provider 미초기화면 `no_provider` → `provider.translate()` 성공 시 UsageLog + TransmissionLogger 모두 기록 / 실패 시 UsageLog status=failed + errorCode 기록.

  - `WebContentsRegistry` — `destroyed` 이벤트로 자동 해제 (메모리 누수 방지).

### G. evaluatePrivacy 흐름 (consent → password → card → text card → domain)

- 임계: 게이트 순서 명확 + 토큰 우회 가능 + 통과 시 토큰 consume.
- 결과:
  - 순서: `!isGloballyConsented` → `consent_revoked` 차단.
  - `hasPasswordField && !hasApproval` → `password_field` 차단.
  - `hasCardField && !hasApproval` → `card_field` 차단.
  - `text && detectCardPatternInText(text)` → `card_field` 차단 (텍스트 본문에 카드번호 패턴).
  - `domainResult.blocked && !hasApproval` → `domain_blacklist` 차단.
  - 통과 + 토큰 사용 → `consumeApprovalToken` 호출 → `user_approved`. 토큰 없으면 `allowed`.
- 판정: **Pass**
- 근거: 5단계 모두 코드로 명확히 분리됨. 토큰은 `consent.validateApprovalToken(token, domain)`에서 도메인 일치 검증 후 통과 시 1회 소비. 본문 카드 패턴 검사는 토큰 우회 불가능 (안전 측면). 단, 의도된 동작인지 명시 — 본문에 카드번호 들어 있으면 사용자 승인 토큰이 있어도 차단. 향후 정책 정렬 가능성 메모.

### H. Preload contextBridge (6개 API 노출, 직접 ipcRenderer 차단)

- 임계: `contextIsolation` + `contextBridge.exposeInMainWorld`로만 노출, Renderer가 ipcRenderer 직접 접근 불가.
- 결과:
  - 노출 API 6개: `browserApi` / `consentApi` / `credentialApi` / `privacyApi` / `usageApi` / `translateApi`.
  - 각 API는 `ipcRenderer.invoke` 래퍼만 export, 직접 ipcRenderer 객체 자체는 노출하지 않음.
  - 타입(`BrowserApi` ~ `TranslateApi`) export로 Renderer 측 d.ts 활용 가능.
- 판정: **Pass**
- 근거: contextBridge로만 노출, Renderer 어디에도 `ipcRenderer` 직접 import 없음 (renderer 코드 grep 검증). API 표면 명확.

### G-005 OS Keychain 위임
- `safeStorage.encryptString` 사용, `credentials.json`에 base64 암호화값만 저장.
- `decryptSecret` 반환값은 `OpenAIApiKeyProvider`의 클로저 호출 시점에만 평문화 → fetch 호출 직후 GC 가능. 인스턴스 필드로 보관 없음.
- 판정: **Pass** (한계: V8 GC 시점까지 string 객체 잔존은 Electron 일반 한계, 명시 사유 아님)
