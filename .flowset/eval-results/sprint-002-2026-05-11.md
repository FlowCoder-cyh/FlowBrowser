## Sprint Retrospective

### 잘된 점
1. **계획대비 일관된 진행** — M1→M2→M3→M4 순서대로 각 마일스톤이 단독 evaluator Pass (13/11/13) 후 머지. 누락 없이 5개 AC 모두 Pass.
2. **테스트 자산 누적** — Sprint 001 47개 → M2 60개 → M4 70개. ParagraphExtractor 단위 테스트 10개로 정규식 / 길이 / 중복 / 청크 단계 직접 검증.
3. **Privacy 게이트 일관성 유지** — paragraph 모드도 evaluatePrivacy 단일 호출 → 전 문단 동일 결정. G-004 정합 유지하면서 성능 챙김.
4. **CI 게이트 강화** — ESLint 9 flat config + lint 단계가 typecheck/test/build 앞단에 배치되어 빠른 실패. 0/0 상태로 시작 가능.
5. **TranslationCache PRD 1:1 정합** — 5요소 복합 키 / TTL 분기 (자막 365일) / LRU trim / glossaryVersion invalidation까지 PRD §12.4 모두 코드화.

### 어려운 점
1. **WebContentsView ↔ TranslationPanel 좌표 동기화** — PANEL_WIDTH 420 / resize 이벤트 / panel:set-open IPC 3축을 모두 묶어야 함. 초기 리스크 #3 그대로 발현했고 inset 재계산으로 해소.
2. **차단 break 조건 문자열 매칭** — 현재 `'전역 동의' | '비밀번호' | '결제'` reason 문자열 기반. M3 평가 시 권고된 대로 PRD §9.6 / 온톨로지에 `pageWideBlock: boolean` 후보 기록 필요.
3. **LRU trim 직접 측정 테스트 부재** — M2 평가에서 권고된 maxBytes 초과 trim 단위 테스트는 M4에서 보강되지 않음 (현재 통과에는 영향 없음).

### 학습
1. **마일스톤 단위 evaluator + Pass 카운트 임계가 동작함** — 누적 37개 Pass 중 단 1개 Partial/Fail 없이 진행. 임계 8은 충분히 보수적이고, 단계별 게이트가 잡음 없이 진행됨.
2. **Privacy 게이트는 1회 스캔으로 충분** — 문단 N개에 N회 호출하지 않고 페이지 1회 스캔 결과를 컨텍스트 주입하는 패턴이 G-004와 성능을 동시 만족.
3. **cache 흐름은 popup 표시까지 확장 필요** — preload PopupResultPayload에 fromCache까지 전파해야 사용자가 ✓ 캐시 표기를 본다. 백엔드만 만들면 비가시.
4. **ESLint 9 flat config 호환** — electron-vite와 충돌 없음 확인. minimal 설정 폴백 불필요.
