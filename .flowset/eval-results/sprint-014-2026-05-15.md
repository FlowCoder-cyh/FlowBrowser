## 항목별 채점

### AC-1 DeviceCodeFlow + CodexLoginProvider 코어 (S014-T01 ~ T03, T07)

- **임계**:
  - `DeviceCodeFlow.generatePkce()` / `requestUserCode` / `pollToken` / `refresh` 응답 매트릭스
  - `CodexLoginProvider.translate` 401 → refresh 1회 재시도 → 실패 시 ProviderError auth_invalid
  - CredentialsStore OAuth 토큰 묶음 (JSON) safeStorage 암호화 + JSON 파싱 헬퍼
- **결과**:
  - **M1**: 사용자 직접 지적("endpoint URL은 Codex CLI 소스 정확성 검증 후 갱신")을 반영하여 RFC 8628 표준 PKCE 자체 생성 변형 → "Codex 서버 발급 PKCE" 흐름으로 갱신. `DEFAULT_ISSUER=https://auth.openai.com`, `DEFAULT_CLIENT_ID=app_EMoamEEZ73f0CkXaXp7hrann` 공개 클라이언트 ID 재사용. `requestUserCode` → `/api/accounts/deviceauth/usercode`, `pollOnce` → `/api/accounts/deviceauth/token` (200 success / 403·404 pending / 그 외 error), `exchangeTokens` → `/oauth/token` (PKCE 서버 발급), `refreshTokens` (회전 처리 — refresh_token 미반환 시 기존 유지)
  - **CodexLoginProvider**: ProviderAdapter 구현, `ensureFreshToken()`이 만료 60초 이내 자동 refresh, `translate`에서 401/403 시 refresh 1회 재시도. 재시도도 실패면 `ProviderError('auth_invalid', retryable=false)` throw → services.ts 폴백 트리거. estimatedCostUsd=0 (Phase 1 PoC #1 실측 대기)
  - **M2**: `makeCodexTokenAccess`(`services.ts:770-787`)가 `CredentialsStore.decryptSecret('codex')` → JSON.parse → TokenBundle 반환, `update`는 fire-and-forget으로 `credentialsStore.upsert({ authType:'oauth', secret: JSON.stringify(bundle) })` 호출 — **OS Keychain (safeStorage) 위임 + JSON 파싱 헬퍼** 모두 통합. M1 단독 Partial이었던 CredentialsStore OAuth 항목이 M2에서 정확히 해소.
- **판정**: **Pass**
- **근거**: M1 평가에서 Partial이었던 "CredentialsStore OAuth 토큰 묶음 round-trip"이 M2 `makeCodexTokenAccess`로 통합 완료. AC-1 명세상 401 → refresh 1회 재시도 → ProviderError auth_invalid 신호의 회로 전체가 `CodexLoginProvider.translate` ↔ `services.ts:executeTranslateRequest`에 깨끗하게 분리 구현됨. PKCE 흐름이 RFC 7636 표준 자체 생성에서 Codex 서버 발급 변형으로 갱신된 점은 사용자가 명시적으로 "Codex CLI 소스 정확성 검증 후 갱신"을 지시한 결과이므로 계약 위반 아님 (Spike 1 조건 3 "device-code+PKCE 직접 구현"은 Codex가 채택한 변형 그대로 구현하는 것이 정합).

- **임계**:
  - `rebuildAllProviders()`에서 codex credential active 시 CodexLoginProvider 인스턴스 등록
  - 401 + refresh 실패 시 credential status='expired' + OpenAI API Key 폴백
  - `UserSetting.defaultProviderId`가 'codex'일 때 토큰 무효면 즉시 'openai' 자동 전환 (BYOK 폴백 — G-011 조건 5)
- **결과**:
  - **rebuildProvider codex 분기** (`services.ts:754-764`): `providers.set('codex', new CodexLoginProvider({ tokenAccess: makeCodexTokenAccess() }))`. `rebuildAllProviders` (line 901-907)에서 status='active' credential만 재구성.
