## 항목별 채점

### A. AC-1 LRU trim 검증 (S003-T01)

#### A-1. maxBytes 초과 시 persistOnce 후 캐시 항목 ≤ 절반
- 임계: 캐시 항목 수 ≤ 원래의 절반
- 결과: `tests/unit/storage/TranslationCache.lru.test.ts` "persistOnce trims to ~half when serialized size exceeds maxBytes" (maxBytes=800, 12회 store) → `expect(sizeAfter).toBeLessThanOrEqual(Math.floor(ITEM_COUNT / 2))` 통과. flush 후 디스크 직렬화 크기 ≤ 800 검증 포함.
- 판정: **Pass**
- 근거: 테스트가 단순 size 검사뿐 아니라 디스크 영속본의 바이트 크기까지 직접 측정. Sprint 002 evaluator §3 후속 1이 요구한 "절반 trim 직접 측정"을 충족.

#### A-2. lastAccessedAt 오래된 항목 우선 제거 (LRU 의미 검증)
- 임계: 가장 오래 사용된 항목이 우선 제거 / 최근 사용 항목은 보존
- 결과: "keeps most-recently-accessed entries after trim" (maxBytes=4500, 6개 store 후 idx=0 lookup으로 lastAccessedAt 갱신 → idx=6,7 추가 store로 trim 트리거) → idx=0 항목이 survivor에 남음을 직접 검증.
- 판정: **Pass**
- 근거: `lastAccessedAt` 갱신 → 정렬 순서 변경 → 상위 절반 보존이라는 LRU 의미를 시간 차(`setTimeout(5ms)`)로 확보하고 검증. Sprint 002 evaluator가 지적한 "오래된 항목 제거 직접 측정" 요건 충족.

#### A-3. maxBytes 미초과 시 trim 미발생
- 임계: 임계 미달이면 모든 항목 보존
- 결과: "trim only occurs when size exceeds maxBytes" (maxBytes=1MB, 12개 store) → `expect(cache.size()).toBe(ITEM_COUNT)` 통과.
- 판정: **Pass**
- 근거: 조건 분기 회귀 가드. trim 부작용이 임계 초과 시에만 발생함을 명시.
