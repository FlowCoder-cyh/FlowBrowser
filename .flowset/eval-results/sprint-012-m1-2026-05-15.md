### A3. captureActiveTabThumbnail() 활성 탭 변경 직전 발동 — AC-1 (핵심)
- 임계: 활성 탭 변경 직전 직전 active view를 ThumbnailStore에 저장.
- 결과: `index.ts` L486~494 `setActiveTabView()` 안에서 호출:
  ```ts
  const prevId = tabManager.getActiveId()
  if (prevId !== null && prevId !== tabId && tabViews.has(prevId)) {
    void captureActiveTabThumbnail()
  }
  ```
  그러나 모든 caller (tab:switch / tab:open / tab:close / tab:close-others / tab:close-right / tab:duplicate / initializeTabs)는 `setActiveTabView(id)`를 호출하기 **전**에 `tabManager.switch/open/close/closeOthers/closeRight/duplicate/restore` 등으로 activeId를 먼저 새 id로 변경한다. 결과적으로 `setActiveTabView` 진입 시점에 `tabManager.getActiveId()`는 이미 **새 tabId와 동일**한 값을 반환하고, `prevId !== tabId` 조건이 false가 되어 캡처는 **어떤 경로에서도 발동하지 않는다**.
  - 추가로 `captureActiveTabThumbnail()` 함수 본문 L464~480도 다시 `tabManager.getActiveId()`로 prevId를 얻으므로, 가령 setActiveTabView의 가드를 통과해도 새 활성 view를 캡처하게 됨 (의도와 정반대).
- 판정: **Fail**
- 근거: 단위 테스트가 ThumbnailStore 자체와 cycleActiveTabId 순수 함수만 다루기 때문에 자동 검증으로 잡히지 않았고, capture hook이 사실상 dead code 상태. M2 hover 미리보기 UI는 항상 placeholder만 표시될 가능성이 큼.
