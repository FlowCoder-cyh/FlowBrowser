### 4. G-003 (인증 금지선) 위반 여부

- 임계: 공개 클라이언트 재사용이 (a) ChatGPT 웹 쿠키 재사용, (b) 비공식 토큰 추출, (c) 사용량 우회, (d) 계정 프록시화 중 어느 하나와도 명확히 구분되어야 함.
- 결과:
  - **(a) 쿠키 재사용**: No — "표준 OAuth device-code grant 사용, 쿠키 미사용" (spec 5번 표). 사용자가 브라우저에서 직접 발급받은 user_code를 입력하는 표준 흐름이며 ChatGPT 웹 세션·쿠키를 앱이 읽지 않음.
  - **(b) 비공식 토큰 추출**: No — "OpenAI가 발급하는 정상 access/refresh token". Codex CLI 인증을 우회하거나 디스크에서 토큰을 훔치는 행위가 아니라 동일 device-code flow를 직접 구현.
  - **(c) 사용량 우회**: No — "OpenAI가 사용자 한도(예: 5시간/주) 강제, 우리는 우회 안 함". 토큰에 묶인 한도를 그대로 받음.
  - **(d) 계정 프록시화**: No — "사용자가 본인 계정으로 로그인, 앱이 대리 로그인 안 함". 앱이 사용자 자격증명을 보관하거나 다른 사용자에게 위임하지 않음.
  - **OpenAI ToS**: 회색 — 명시적 위반 조항 발견 못함, 공식 등록 경로 없음. 회색지대를 회색지대로 정확히 라벨링.
- 판정: **Pass**
- 근거: G-003의 4개 금지 항목 모두에 대해 명확한 No 판정 + 근거. 특히 "공개 클라이언트 ID 재사용"과 "비공식 토큰 추출"의 구분이 명료(전자=표준 OAuth flow 직접 구현, 후자=Codex CLI 우회). 회색지대는 회색지대로 솔직하게 라벨링. G-003 자동 Fail 조건 미해당.

### 9. 사용자 의견 반영 흐름 (Fail → Pass with conditions 재조정)

- 임계: 초기 판정과 최종 판정이 다른 경우, 재조정 근거(사용자 의견 / 새 자료 / 가드레일 변경)가 spec에 명시되어야 함. "그냥 바꿨다" 금지.
- 결과:
  - spec 변경 이력: "2026-05-11: placeholder 생성" → "2026-05-11: 1차 조사 완료, Pass with conditions 판정. Phase 1 PoC 이관 항목 4개 명시" — 단일 일자 내 갱신
  - 재조정 근거의 spec 본문 트레이스:
    - **§3 3rd-party 앱 사례**: OpenClaw / Roo Code / anomalyco 다수 사례 발견 → "OpenAI는 공식 인정도 차단도 안 함 = 사실상 묵인 / 회색지대" 결론
    - **§5 정책 위반 가능성 평가**: G-003 4개 금지 항목 모두 No 판정 (쿠키 미사용 / 정상 토큰 / 한도 우회 안 함 / 계정 프록시화 안 함)
    - **§판정**: "Pass with conditions" + 조건 5개로 재조정 — 사용자가 본 흐름을 검토한 결과 Experimental 라벨로 유지 결정
  - phase0-summary §4.3에서 "초기 Fail → Pass with conditions 재조정" 흐름이 "사용자 의견 반영"으로 명시되며, 본 사후 evaluator 호출의 명분으로 사용됨
  - 본 사후 평가는 G-011 신규 추가(2026-05-11) 이후 진행 — Spike 1 spec과 G-011이 일관한지 별도 검증 항목(§5)으로 처리
- 판정: **Pass**
- 근거: 재조정 근거가 spec 본문 §3·§5·판정 섹션에 트레이스 가능. 회색지대 판정(공식 명시 부재 + 차단도 없음 + 다수 사례) → Pass with conditions 결론의 논리 흐름이 일관. G-006(추측 금지) 위반 없음. 다만 spec 자체의 "변경 이력" 섹션이 placeholder → 1차 조사 완료 2단계만 기록되어, "Fail 검토 단계"가 명시적으로 보존되지 않은 점은 사후 트레이스 한계 — 본 evaluator 보고서가 그 보완.
