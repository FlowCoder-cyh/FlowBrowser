### AC-5 (1) — 페이지 URL 정규화 + 노드 해시
- 임계: URL 정규화 (쿼리/프래그먼트 제외) + 노드 해시 기반 키
- 결과:
  - `normalizePageUrl` (`PageResultStore.ts:56-64`) — `new URL` 파싱 후 `${u.origin}${u.pathname}` 반환, 파싱 실패 시 `raw.trim()` fallback
  - `nodesSignatureFromTexts` (`:69-72`) — `${id}|${text}` join 후 sha256, 32자 hex slice
  - `buildKey` (`:74-83`) — 정규화된 URL + targetLanguage + providerType + glossaryVersion(`'default'` fallback) join 후 sha256 32자
  - 단위 테스트 검증:
    - `normalizePageUrl strips query and fragment` PASS (`?q=1#frag` → `/path`만 남음)
    - `query/fragment is ignored — normalized URL` PASS (store URL `?x=1` ↔ lookup URL `#frag` 동일 키 hit)
    - `different glossaryVersion → different key (miss)` PASS
    - `nodesSignature mismatch returns null` PASS
- 판정: **Pass**
- 근거: 정규화·해싱 구현 + 4건 단위 테스트로 동작 입증.

### AC-5 (2) — TTL 30일 + 디스크 한도 500MB
- 임계: TTL 30일 기본 + 500MB 한도 + 한도 초과 시 LRU 처리
- 결과:
  - `DEFAULT_TTL_MS = 30 * 24 * 60 * 60 * 1000` (`:49`) → 30일 정확
  - `DEFAULT_MAX_BYTES = 500 * 1024 * 1024` (`:50`) → 500MB 정확
  - `lookup` 만료 시: `entry.expiresAt < now` → `memory.delete(key)` + `scheduleWrite()` → null 반환 (`:125-130`)
  - `load` 후 `purgeExpiredSync` 호출로 디스크에서 읽은 만료 항목도 제거 (`:114, 213-220`)
  - `persistOnce` LRU trim: 직렬화 후 `Buffer.byteLength(serialized) > maxBytes` 시 lastAccessedAt 내림차순 정렬 → 절반만 보존 → 메모리·디스크 동기 갱신 (`:231-238`)
  - 단위 테스트 검증:
    - `expired entry is removed on lookup` PASS (ttlMs=1, 20ms 대기 후 lookup → null + size 0)
    - `LRU trim when maxBytes exceeded` PASS (maxBytes 1500, 6개 항목 store → size ≤ 3)
- 판정: **Pass**
- 근거: 상수값 정확, lookup 만료 처리·LRU trim 모두 단위 테스트로 입증.
